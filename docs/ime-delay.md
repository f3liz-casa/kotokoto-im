# IME 切り替えの遅延 調査メモ

目的: 「いちばん速く」ではなく「いつも同じ時間で」切り替わるようにする。毎回同じ遅れなら体がタイミングを覚えるが、速い日も遅い日もあると、打ち始める前に毎回確かめることになる。

この環境(Linux)では実機計測ができない。以下は、ソースの読解と公開情報から分かったことと、実機で測るための手順。**測定値はまだ無い**。

## 遅れが生じる箇所

1. **切り替え要求 → システムの通知**: `TISSelectInputSource` を呼んでから `kTISNotifySelectedKeyboardInputSourceChanged` が届くまで。
2. **通知 → 入力先アプリの入力メソッドが使える**: 通知のあとに少し間がある。この間に打ったキーは切り替え前の入力ソースに届く。
3. **入力メソッド内部の状態**: 入力ソースは日本語になっても、IME 自身が「直接入力(英数)」のままのことがある。

| 事実 | 出典 |
| --- | --- |

## 方針案: 一定の遅れにする

- **入力は預かって、決めた時刻に返す**: 切り替え要求の時刻から一定の時間 `T` が経つまで、キー入力を預かる(今は「通知 + 30 ms」で返すので、遅れが毎回違う)。
  - 通知が `T` より早く来ても、`T` まで待つ。→ 遅れが一定になる。
  - 通知が `T` より遅いときだけ、通知まで延びる。→ `T` を十分大きく(測定の p95〜p99 + 余裕)取れば、ほぼ起きない。
- `T` は設定にする(例 `switchLatency`、ミリ秒)。`0` なら今の挙動(着き次第)。
- 遅れの長さと一定さはトレードオフ。`T` を大きくするほど一定にできるが、毎回その分だけ待たされる。体感で許容できる最小の `T` を選ぶ。
- 言語インジケーターを切ると、切り替え自体が速く・ばらつきが小さくなる可能性がある(未検証)。システム全体の設定なので、このツールは自動では変更しない。

## 実機で測る

```sh
build/kotokoto-im.app/Contents/MacOS/kotokoto-im --bench
```

遷移(英語→日本語など)ごとに、選択から (a) システムの通知、(b) 現在の入力ソースが狙いに変わる、までの時間を 10 回ずつ測り、最小 / 中央 / p95 / 最大を出す。最後に、全遷移で着くのに必要な待ち時間の目安を出す。

測れないもの: 入力先アプリの入力メソッドが実際に使えるようになるまでの時間(通知より遅れることがある)。これはアプリの種類でも変わる可能性があり、実際に文字を打って確かめる必要がある。

確かめたいこと:

1. 遷移ごとの中央値とばらつき(英語⇔日本語が、日本語⇔韓国語より遅く、ばらつくか)。
2. 言語インジケーターを切ると、ばらつきが小さくなるか。
3. Firefox の検索欄など、アプリによって遅れが違うか。
4. 標準の日本語入力と Mozc / Google 日本語入力で違うか。

## 「表示は日本語なのに英字が入る」の正体と対処

- **原因**: 遅れではなく、Mozc の内部モード。`trace` のログで、最後の切り替えから 7〜11 秒後に打ったキー(入力ソースは Mozc)でも `a` が入力された。入力ソース ID は `org.mozc.inputmethod.Japanese.base`(ひらがな)なのに、Mozc 自身は直接入力モードのまま。cmd-ime issue #4 と同じ症状。
- **対処**: 入力ソースを直接選ばず、かなキー(104)を送って macOS に任せる(⌘英かな 方式)。実機(Mozc、Dvorak-QWERTY⌘、macOS 27.0.1)で、英語→日本語を 10 往復し、打った文字が `aあaあ…` と交互になることを確認(`u0010` も出ない)。ログでは「キー送信: かな」の約 15〜20 ms 後に通知が届き、Mozc になっていた。
- 条件: 現在の入力ソースが狙いのときは送らない(Mozc が処理しないモードで送ると `u0010` が入力される)。つまり、すでに Mozc で内部モードだけが直接入力になっている場合は直せない。

## 試して外したこと

- **「かな」キーを送る(`sendKanaKey`)**: 入力ソースが Mozc に着いたあと(通知の約 30 ms 後)に、かなキー(キーコード 104)を送って、IME をひらがなモードにする案。cmd-ime issue #4 の提案どおり。実機(Mozc、Dvorak-QWERTY⌘ 配列)で、Firefox の検索欄に制御文字 `u0010` が入力された。Mozc が、そのときのモードではこのキーを処理せず(すでにひらがなモードなど)、アプリが文字として受け取ったと考えられる。IME の内部モードはこちらから見えないので、モードを知らずに送るのは不適切と判断して機能ごと外した。
- **実測(`--bench`、macOS 27.0.1)**: システムの通知は 5〜18 ms、現在の入力ソースへの反映も同程度で、遷移による差は小さい。ツールが要求してからキーを返すまでは、約 43〜47 ms で一定だった(8 回)。
